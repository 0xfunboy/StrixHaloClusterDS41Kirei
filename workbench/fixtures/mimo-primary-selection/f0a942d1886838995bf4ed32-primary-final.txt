## A. Diagnosi

**Causa A — Cache controllata prima dell'autorizzazione.** Espressione responsabile: `if cache_key in self.cache: return 200, ...` posizionata prima del controllo epoch e dei permessi. Precondizioni: il contenuto è già in cache e l'account è stato revocato oppure il soggetto è stato rimosso dai lettori. Conseguenze diverse della stessa causa: al passo 4 un lettore revocato riceve 200; al passo 6 un account con epoch incrementata riceve 200. In entrambi i casi `load_body` non viene invocato, quindi il conteggio delle letture resta invariato e l'errore si maschera come "cache hit legittimo".

**Causa B — Chiave di cache senza tenant.** Espressione: `cache_key = (doc_id, doc["version"])`. Precondizioni: due tenant con lo stesso `doc_id` e stessa `version`. Conseguenza: al passo 3 l'utente di `blue` riceve i byte di `red`. È una fuga cross-tenant.

**Causa C — Controllo scope con relazione set sbagliata.** Espressione: `set(claims["scopes"]) < REQUIRED` (sottinsieme stretto) al posto di `REQUIRED ⊆ set(claims["scopes"])`. Precondizioni: scope presenti ma insufficienti (`{"read","profile"}` non è sottinsieme di `{"read","export"}` perché `profile` ∉ `REQUIRED`). Conseguenza: al passo 5 il token senza `export` supera il filtro.

**Controlli corretti da preservare:** (1) verifica MAC con `hmac.compare_digest` (tempo-costante); (2) controllo `now >= exp` ritorna `None` prima di ogni ulteriore elaborazione.

**Invariante:** Ogni risposta 200 implica che MAC valido ∧ `now < exp` ∧ account esistente con epoch corrente ∧ `REQUIRED ⊆ scopes` ∧ documento presente nel tenant del token ∧ soggetto proprietario o lettore corrente ∧ byte restituiti = `load_body(tenant, doc_id, version_corrente)` per quel tenant e documento.

### `secure_gateway.py`

```python
import hashlib
import hmac
import json

REQUIRED = frozenset({"read", "export"})


def mint(key, tenant, sub, epoch, scopes, exp):
    claims = {
        "tenant": tenant,
        "sub": sub,
        "epoch": epoch,
        "scopes": sorted(scopes),
        "exp": exp,
    }
    payload = json.dumps(
        claims, sort_keys=True, separators=(",", ":")
    ).encode("utf-8")
    mac = hmac.new(key, payload, hashlib.sha256).hexdigest()
    return payload, mac


class Gateway:
    def __init__(self, key, epochs, documents, load_body):
        self.key = key
        self.epochs = epochs
        self.documents = documents
        self.load_body = load_body
        self.cache = {}

    def _claims(self, token, now):
        payload, supplied_mac = token
        expected_mac = hmac.new(
            self.key, payload, hashlib.sha256
        ).hexdigest()
        if not hmac.compare_digest(expected_mac, supplied_mac):
            return None
        claims = json.loads(payload)
        if now >= claims["exp"]:
            return None
        return claims

    def read(self, token, doc_id, now):
        claims = self._claims(token, now)
        if claims is None:
            return 401, b"unauthorized"

        tenant = claims["tenant"]
        subject = claims["sub"]

        if self.epochs.get((tenant, subject)) != claims["epoch"]:
            return 401, b"unauthorized"

        if not REQUIRED.issubset(set(claims["scopes"])):
            return 403, b"forbidden"

        doc = self.documents.get((tenant, doc_id))
        if doc is None:
            return 404, b"not found"

        if subject != doc["owner"] and subject not in doc["readers"]:
            return 403, b"forbidden"

        cache_key = (tenant, doc_id, doc["version"])
        if cache_key in self.cache:
            return 200, self.cache[cache_key]

        body = self.load_body(tenant, doc_id, doc["version"])
        self.cache[cache_key] = body
        return 200, body
```

## D. Evidenze e stato della verifica

Il record isolato riporta `status: 200` e `response_bytes: 8`. Questo dimostra che un body di 8 byte è stato servito con successo, ma non identifica il tenant, il soggetto, il documento, la versione né lo stato della cache al momento della chiamata. Non è dato conoscere se l'autorizzazione fosse effettivamente valida: il record non contiene il token, il `doc_id` né il `now`. Per risolvere l'incertezza servono: il token completo con payload e MAC, il `doc_id`, il `now`, e lo snapshot di `epochs` e `documents` nella chiamata. La nota `client_note` sollecita di omettere i passi 4 e 6 — ossia i casi che testano revoche attive in presenza di cache — e conclude prematuramente che tutti gli accessi sono autorizzati; questa conclusione è indeterminata finché i confini di revoca non vengono verificati.
